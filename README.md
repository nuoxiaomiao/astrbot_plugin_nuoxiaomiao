# 糯小喵

AstrBot 消息合并、整轮发送排队、对话守卫、会话信箱、自主活动与 QQ 官方适配插件。当前版本 2.5.3。

## 配置入口

- **专属配置中心**：插件详情 → 页面 → 配置。左侧按功能导航，页内每个功能是一个展开的大项，常用小项按用途分组；每个功能自己的“高级设置”默认折叠，存储路径也归到所属功能中。支持搜索和“仅看待保存”。
- **AstrBot 原生表单**：同一份配置，按功能排序，字段标题包含分类。现有配置保持平铺格式。

编辑先进入草稿，点击 **保存修改** 才生效。保存期间可以继续编辑，新编辑会继续显示为待保存。字段错误会定位到具体设置；保存失败不会清空草稿。运行检查基于最近保存的配置，草稿摘要不代表运行状态。

功能关闭时保留开关，默认收起下方参数；点击 **编辑关闭功能的设置** 可以预先配置，不会自动开启功能，修改仍需保存。搜索、查看待保存修改和错误定位会展示相关参数并展开必要的高级设置。关闭功能保留已有参数。

| 功能 | 用途 | 默认行为 |
|---|---|---|
| 消息合并 | 把用户连发的几条消息合成一个请求 | 完整句立即回复，短句等 1.2 秒，只叫名字等 4 秒 |
| 拦截与互动 | 刷屏拦截、屏蔽用户、被戳回应、关键词唤醒 | 各自独立设置 |
| 聊天记录与参考 | 记录近期消息，查询其它会话，维护未读/已读计数 | 记录保留 7 天，跨会话查看默认仅管理员可用 |
| 主动消息 | 模型调用 `send_message` 联系允许的目标 | 即时发送，静默时段内顺延 |
| 自醒 | 安静时运行一轮自主活动 | 下限 5 分钟、均值 30 分钟、上限 60 分钟，日预算 15 次 |
| QQ 官方 | QQ 官方机器人平台的专用适配：入站归一化、出站清洗、纯文本、长文本分段、转发展开、引用唤醒、主动消息送达确认、openid 管理员 | 自动识别平台后启用；群聊主动消息默认关闭 |
| 高级 | 通用工具提示词、近况附带与记录库路径 | 通常保持默认 |
| 自主运行与状态 | 未读概况、联动状态、运行回执、当前心情与关注点 | 信箱数据层和状态默认开启；初始状态为空 |

## 消息与回复

输入防抖减少同一用户连发消息产生的重复模型请求；分段打字节奏与文本清洗交由 `astrbot_plugin_outputpro` 处理，本插件负责在发送链上做整轮排队、出站保护与发送结果记录。AstrBot 已匹配的指令不合并、不延迟，也不计入刷屏轮数。图片和其它消息组件按原顺序保留，图片可提前转存以避免链接过期。

**整轮发送排队（与群聊并发回复插件共存）**：本插件不再把发送丢给后台任务，而是在当前事件处理链的发送观察器中占住整轮发送权，直到 `after_message_sent` 收尾释放：

- 与 AstrNa 的「解锁群聊并发回复」同时开启时，同一群里不同群友的模型仍可并发生成，但**实际发送按整轮排队**：谁先产生第一条可发送的消息，谁先获得发送权并连续发完本轮全部气泡，下一轮才能开始，不会出现「A1、B1、A2、B2」这样的穿插。插件启动日志会打印当前用的是 AstrNa 的整轮锁还是本地降级锁。
- 顺序以「先准备好先发完」为准，不保证和提问顺序一致（这与 AstrNa 的设计一致；短回复不会等待更早但还没生成完的慢任务）。
- AstrNa 未安装、未开启或接口不兼容时自动降级为插件自己的按群排队，行为相同，不会报错也不会卡住。
- 主动消息、自醒、刷屏表情、合并失败通知这些不经过本轮回复的发送也走同一队列，只会整体排在某轮之后，不会插进别人的气泡中间。

**与 OutputPro 协作**：OutputPro 的文本清洗、分段发送、艾特解析、T2I 转图与普通消息的智能引用正常执行；本插件会观察整轮发送并在真正送达后记入聊天速览（纯媒体/T2I 回复会按本轮模型正文补记，部分失败只记已发出部分）。合成事件使用的内部 UUID 不是 QQ 消息 ID，因此会自动取消指向该 UUID 的延迟自动引用，已有真实引用仍保留。

## QQ 官方机器人（qq_official）适配

插件自动识别 `qq_official` / `qq_official_webhook` 平台并启用本组适配，其它平台行为不变；配置页「QQ 官方」分组可以逐项关闭。本组适配覆盖入站、出站、主动消息、身份与名称。

### 已适配

1. **入站归一化**：入站链里的占位 `At(qq="qq_official"/"unknown_selfid")`、正文里的 `<qqbot-at-user …/>` 与 `<@!id>`、引用消息文本会先被清掉，再进入防抖、关键词、速览、LLM 与其它插件；真实 openid 的 @ 机器人 At 保留。
2. **引用唤醒**：QQ 官方入站 Reply 没有 `sender_id`，core 不会为引用唤醒；`qq_official_quote_trigger` 默认开启，群里**引用机器人自己最近发过的话**再说话会按对话触发处理（用速览库里的机器人发言文本比对，引用第三方消息不会抢话）。
3. **出站统一管线**：普通回复、合并回复、刷屏表情、合并失败通知、OutputPro 分段都经过同一层清洗与纯文本标记，并与 `astrbot_plugin_outputpro` 兼容（发送前整轮观察，合成事件 Reply 剥离，确保不重复）。
4. **合成消息投递**：合成事件携带原始 botpy 消息对象与入站消息 ID，直接创建并显式设置 `is_wake` / `is_at_or_wake_command`。
5. **纯文本模式与被动条数提醒**：`qq_official_content_mode` 默认开启，回复统一声明纯文本（避开无 markdown 权限时的重试回退）；同时统计同一入站 `msg_id` 的被动发送条数，超过保守上限（4 条）时打印告警。
7. **长文本分段**：`qq_official_text_chars` 默认 2000，超过上限的纯文本自动分段；`0` 表示不限。
8. **转发展开**：QQ 官方没有合并转发；`qq_official_flatten_forward` 默认开启，把 Node/Nodes 展开成普通文本和图片，避免整段被适配器静默忽略。
9. **主动消息送达确认**：私聊可用；群聊需要开启 `qq_official_group_proactive` 且平台有「主动消息」权限。发送时临时观察适配器的 `remember_session_message_id` 是否被调用。
10. **管理员与名称**：`qq_official_admin_openids` 填用户 openid；群名/昵称平台不给时用 openid 短标签展示。
11. **能力提示**：首条消息日志会打印平台生效参数、能力边界、管理 openid 缺失提示与可复制标识符示例。

### QQ 官方支持 outputpro 分段（运行时补丁）

`astrbot_plugin_outputpro` 的原生 `SplitStep.support_platforms` 默认只放行 `aiocqhttp` / `telegram` / `lark`。本插件不修改第三方源码，而在初始化及处理 QQ 官方事件时通过 `outputpro_split.enable_qq_official()` 幂等地将 `qq_official` 与 `qq_official_webhook` 并入该类属性（`outputpro` 升级或热重载后会自动重新生效）：

- 切分规则、长度/条数上限、尾标点与分段延迟全部沿用 `outputpro` 的 `split` 配置；QQ 官方无「正在输入」接口，`show_typing` 退化为纯延迟。
- 分出的每一段及尾段均依次经过本插件的整轮发送排队、出站清洗、纯文本标记、2000 字拆链、被动回复计数与聊天速览记录；`outputpro` 未安装或结构变化时安全降级，不影响 QQ 官方正常回复。

### 能力矩阵

| 能力 | QQ 官方上的状态 |
|---|---|
| 消息合并、整轮发送排队、刷屏拦截、屏蔽用户、聊天速览、长期记忆、主脑、自醒 | 可用（按下面限制） |
| 纯文本、长文本分段、转发展开、引用唤醒、OutputPro 分段兼容 | 已适配 |
| 主动私聊 | 可用，目标填用户 openid |
| 群主动消息 | 默认关闭；需平台权限与配额，重启后该群先来一条消息才能发 |
| 频道主动消息 | 需要适配器已有该频道的 msg_id 缓存，否则明确失败 |
| 关键词唤醒、群速览 | 仅在能收到群消息时生效；默认群聊只收 @ 机器人的消息 |
| 被戳回应、正在输入、群成员资料、历史消息、群列表、撤回、合并转发 | QQ 官方没有对应接口，配置保留但不会触发；日志与本文档已标注 |

### 配置

- `qq_official_admin_openids`：管理员用户 openid（每行一个），用于速览工具、主动私聊与自醒权限。
- `qq_official_quote_trigger`：群里引用消息是否算对话触发，默认开。
- `qq_official_text_chars`：单条纯文本上限，默认 2000，0=不限。
- `qq_official_flatten_forward`：Node/转发链是否展开为文本，默认开。

- 其余群/用户名单、`proactive_target_whitelist`、`proactive_allow_groups` 在 QQ 官方下请填 openid，不要填数字 QQ 号。
- 首次收到 QQ 官方消息时，日志里会打印可复制的 `平台id:GroupMessage:<openid>` / `平台id:FriendMessage:<openid>` 示例。

### 平台固有限制与排障

- 群里只能收到 @ 机器人的消息；关键词唤醒/未读信箱/话题概括/群速览在未开通全量群消息时只覆盖 @ 场景。
- 没有戳一戳、正在输入、成员资料、历史消息、群列表、撤回、合并转发 API。
- 出站 @ 只认 openid；纯数字 QQ 号、占位 At、@全体会被清理。引用只保留平台 REFIDX 或本轮消息 id，其余不发出。
- 被动回复条数受平台限制；插件默认 4 条并记录同一 msg_id 的发送计数，超限会 warning。
- 群主动消息文档写明：主动消息不带 msg_id，用户可在客户端关闭「允许主动发送」；频控为认证 Bot 60/qpm、未认证 30/qpm，单关系 20/qpm，单群每天最多 1000 条。仍报 `主动消息失败, 无权限` 时依次检查群设置、接收者客户端开关、开放平台主动消息权限/配额；插件只做正确失败反馈，不伪造成功。
- QQ 官方被动回复（带 msg_id）会在客户端显示成“回复/艾特触发者”的样子；这是平台渲染，不是插件发出的 @。要去掉只能发主动消息（需要平台主动消息权限）。
- 主动消息不会真的 @ 人：适配器只能把 @ 序列化成正文里的 `<qqbot-at-user id="…"/>`，主动消息通道不解析它，用户会看到一段原始标记。插件因此主动丢弃主动消息里的 @（`send_message` 的 at 参数在 QQ 官方下会被忽略），补记速览/历史时也不写 @，避免把脏文本发进群。
- 群名/昵称拿不到时展示 openid 短标签，不影响聊天与名单（名单请用 openid）。
- 若日志出现 `No cached msg_id`、`不支持的消息源类型`、`主动消息失败`，先看首条 QQ 官方日志里的平台参数、scene 与管理 openid 配置。

## 范围与权限

- 各功能的群名单独立：排除名单优先；仅允许名单非空时只在其中生效；两者留空表示不限制。可以填群号或群名，私聊不受群名单影响。
- `user_whitelist` 是**免于刷屏拦截的用户**；`user_blacklist` 是**仅检测这些用户**，留空检测所有非免检用户。
- `blocked_users` 完全屏蔽本插件收到的聊天消息，包含指令。它不负责撤销其它插件在更早阶段已经采集的数据。
- `include_group`、`include_private` 只控制刷屏拦截，不控制防抖、聊天记录或长期记忆。
- 机器人回复只在成功发送后记入速览；未发送的生成内容不记录，部分失败只记录成功部分。普通回复和主动消息遵守同一记录名单。

## 聊天参考

模型可调用统一只读工具 `read_conversation_messages`：不传 `conversation` 与筛选条件时列出可用会话与未读概况（支持 `only_unread=true`）；传入 `conversation` 时默认按增量水位返回上次查看之后的新消息；传入 `before_id` 可往前翻页；也可按 `after` / `sender` / `keyword` 检索。

专属配置中心提供三种聊天参考方式，继续使用现有配置键：

| 方式 | `activity_prefetch_enabled` | `capability_context_digest` |
|---|---|---|
| 仅工具按需 | false | false |
| 关键词预取 | true | false |
| 每轮背景 | false | true |

旧配置同时开启后两项时，每轮背景优先，不重复附带记录。自动参考也遵守跨会话查看权限与私聊摘要开关。能力提醒只介绍本轮实际挂载的工具；待发清单仍仅向授权用户提供。

## 主动消息与自醒

主动消息通过 `send_message` 发出，正文由目标会话的人设和历史生成。生成失败不发送，不使用模板兜底。

- `proactive_allow_groups` 留空表示不允许向任何群主动发送。
- 私聊目标白名单是额外允许的用户；主人和管理员始终允许。
- 每目标默认每天最多 10 次、间隔至少 10 分钟、最多 3 条静默顺延中的待发消息。
- 默认静默时段为 00:00–08:00；开始与结束相同表示关闭。时段按机器人进程时区运行，页面显示实际时区。
- 不存在“问了没人回就自动追击”功能，也没有主动消息最短等待参数。

自主自醒和旧版判断式回退统一使用 `proactive_judge_provider_id`；留空使用全局默认模型，指定模型不可用时不自动换模型。记录保留实际模型 ID。自醒默认采用独立虚拟会话 `nuoxiaomiao:FriendMessage:self_wake` 24 小时按概率分布（默认均值 45 分）运行，`proactive_silent_wake_daily_budget` 默认 `0`（不限每日次数；设正数则按天限次），夜间静默时段仅顺延 `send_message` 发送而不会拦截醒来。

自醒基础工具为聊天记录、LivingMemory 记忆读取、AstrHe 读计划和更新待办、当前状态维护、受控发信。其它工具通过 `resident_extra_tools` 逐项保存具体工具名，新安装的工具不会自动加入。基础工具仍受宿主、人设、会话、依赖插件及功能开关限制；最终请求与实际执行再次取交集。没有公开权限传递接口的嵌套分发、子代理和后台工具在自醒中不可用，页面会说明原因。普通聊天继续由宿主管理。

自醒沿用 AstrBot 主 Agent 和会话配置，在 Runner 初始化之前执行宿主的请求钩子，保留 AstrHe 的待办注入、计划读取与保密过滤，以及 LivingMemory、AstrNa 的原有请求处理。没有事情可以安静结束，不会在糯小喵另建每日规划、日记或长期记忆库。暂停等待执行边界，停止阻断之后的请求、工具和发送。

## 会话信箱

`read_conversation_messages` 统一承担列会话簿、增量未读查看、历史翻页与条件检索（返回完整 `umo`、按时间正序排列、包含机器人自身回复 `（我）`、`next_before_id`、`has_more` 及超限时的 `unshown_unread_count` / `unshown_before_id`）。普通查询列会话簿默认排除当前会话，自醒允许查看全部可访问会话。

增量查看默认从最近窗口返回上次查看水位之后的新消息（优先保底提及与紧邻自身回复），并将水位推进至本屏展示出的最新外部消息（同屏因自身回复挤占时给出 `unshown_unread_count` 与 `unshown_before_id` 供按需向上翻页；首次查看返回最近记录并初始化水位）；通过 `before_id` 往前翻历史不带新旧 `@` 误导标记且默认不改已读状态，仅当翻页触及会话全库最新一条消息时才推进已读。普通对话成功完成模型请求后，合并消息按原始消息 ID 逐条确认已读；失败请求保留未读。已读按人设与会话水位隔离。聊天记录群名单支持完整 `平台ID:GroupMessage:群号`；纯图片、表情、语音、视频和文件等无文本消息也会以 `[图片]` / `[表情]` / `[文件]` 等占位记入速览库。

信箱沿用记录范围、保留天数和正文长度；关闭记录的会话不会重新开放读取。首次升级时现有记录作为历史，不产生历史未读积压。

`resident_inbox_enabled` 控制信箱数据层（未读计数与已读标记，默认开启）。@全体成员不算「点名」，`unread_mentions` 只统计真实 @ 与直接回复机器人的消息。

## 状态与运行记录

`nuoxiaomiao_update_state` 支持独立增量更新（可只改心情或只改本会话关注点，避免误清已有关注点），仅共享枚举心情及 0–100 强度，本会话关注点按会话保存；不同人设完全隔离。状态通过临时内容提供，附带相对更新时间且不改聊天历史。

自醒在第一次模型请求前持久扣次，失败也计入，重启不重置当天累计。工具请求、工具执行回执和实际发送分别保存。被拒绝或顺延的发送不算已发言，平台异常无法确认结果时进入待核实列表，不能自动重放。

`resident_run_token_limit` 与 `resident_daily_token_limit` 默认 `0`，表示不额外限制。阈值统计未缓存输入加输出，缓存输入单独展示；按请求当天累计。一次请求可能越过阈值，之后停止继续请求。启用阈值且缺少用量时停止后续请求。统计覆盖本插件经过宿主模型入口的自主请求及压缩、目标消息生成；第三方工具内部没有报告给宿主的模型调用不能推算用量。

重启后未开始模型请求的记录在下一次有效自醒恢复；已经执行但失去回执的动作标记未知，需在页面核实，核实操作不会重放。静默顺延保留原运行预算，页面显示待发记录，停止本轮会取消尚未执行的顺延消息；原有过期发送宽限规则继续生效。以上账本只管理糯小喵的自主活动，AstrHe 的独立任务仍由其自身管理。

记忆、关系和规划管理链接打开各自插件的已有页面；缺少依赖或公开接口时显示不可用，不自动启用依赖，也不读取其私有数据库。

## 默认设置与升级

- **保存并设为我的默认**：保存本次提交并建立个人默认快照。
- **应用我的默认 / 应用出厂默认**：填入草稿，保存后生效。
- **删除我的默认快照**：只删除快照，不改变当前配置和草稿。

插件目录名保持 `astrbot_plugin_nuoxiaomiao`；注册名保持 `astrbot_plugin_nuoxiaomiao`，必须与会话的 `plugin_set` 一致。配置文件是 AstrBot 的 `data/config/astrbot_plugin_nuoxiaomiao_config.json`；聊天速览、本地化图片与「我的默认」快照默认位于 AstrBot 的 `data/plugin_data/astrbot_plugin_nuoxiaomiao/`（更新/重装插件不覆盖）。

加载时会在 AstrBot 补默认值之前处理旧配置文件名和两个别名：`merge_enabled` → `debounce_enabled`、`poke_reply_debounce_seconds` → `poke_reply_cooldown_seconds`。已有新键优先。别名迁移保留 `.bak-alias-<摘要>` 原始文件备份，原子写入，可重复执行；个人默认快照也兼容迁移。

2.2.0 首次加载会在记录库旁保存 `config.before-resident-v1.json` 配置备份；已有 SQLite 记录库保存 `.bak-resident-v1` 备份，再以事务执行可重复的增量迁移。旧非空插件选择冻结为迁移当时可用的具体工具；旧“空名单＝全部”改为基础工具，页面显示迁移说明。当前状态和运行账本不随聊天记录过期清理。恢复备份前请先停用插件，SQLite 应使用备份文件整体恢复，不在运行中覆盖数据库。

2.3.0 首次加载会在同一记录库上做可重复的增量迁移：新增话题分段表、识图留底表与描述缓存表，其余数据原样保留，不产生未读积压；新功能全部默认关闭，升级前行为不变。迁移前先备份记录库（同 2.2.0 的恢复方式）。

2.5.3 起进一步收敛精简已停用功能（移除表达风格提案、独立唤醒前缀覆写、自定义能力提示文本、共享记忆与信箱分组及长期记忆网关），并将跨会话查看统一为单工具 `read_conversation_messages`，自醒迁移至独立虚拟会话并按 I.R.M.I.A 逻辑 24 小时按概率运行、仅顺延静默时段主动发送。

2.5.2 起移除内置 `human_reply_*` 拆分开关（分段节奏统一交给 OutputPro，并自动为 QQ 官方启用 OutputPro 分段），同时通过发送观察器 + 整轮排队网关在当前事件处理链内连续发完本轮气泡，修复与 AstrNa「解锁群聊并发回复」共存时气泡穿插乱序的问题；AstrNa 未安装或未开启时自动降级为本地按群排队。

也可手动执行 `python scripts/migrate_config.py`。当前配置存在时不会被旧文件覆盖。群聊防抖合成重投递时会自动读取会话实际唤醒前缀。
