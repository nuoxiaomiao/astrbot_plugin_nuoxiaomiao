# 糯小喵

AstrBot 消息合并、回复节奏、对话守卫、会话信箱和自主活动插件。当前版本 2.4.0。

## 配置入口

- **专属配置中心**：插件详情 → 页面 → 配置。左侧按功能导航，页内每个功能是一个展开的大项，常用小项按用途分组；每个功能自己的“高级设置”默认折叠，存储路径也归到所属功能中。支持搜索和“仅看待保存”。
- **AstrBot 原生表单**：同一份配置，按功能排序，字段标题包含分类。现有配置保持平铺格式。

编辑先进入草稿，点击 **保存修改** 才生效。保存期间可以继续编辑，新编辑会继续显示为待保存。字段错误会定位到具体设置；保存失败不会清空草稿。运行检查基于最近保存的配置，草稿摘要不代表运行状态。

功能关闭时保留开关，默认收起下方参数；点击 **编辑关闭功能的设置** 可以预先配置，不会自动开启功能，修改仍需保存。搜索、查看待保存修改和错误定位会展示相关参数并展开必要的高级设置。关闭功能保留已有参数。

| 功能 | 用途 | 默认行为 |
|---|---|---|
| 消息合并 | 把用户连发的几条消息合成一个请求 | 完整句立即回复，短句等 1.2 秒，只叫名字等 4 秒 |
| 回复节奏 | 生成后按打字速度逐条发送 | 默认关闭，240 字/分钟，超过 300 字交回原流程 |
| 拦截与互动 | 刷屏拦截、屏蔽用户、被戳回应、关键词唤醒 | 各自独立设置 |
| 聊天记录与参考 | 记录近期消息，查询其它会话，按需检索长期记忆 | 记录保留 7 天，跨会话查看默认仅管理员可用 |
| 主动消息 | 模型调用 `send_message` 联系允许的目标 | 即时发送，静默时段内顺延 |
| 自醒 | 安静时运行一轮自主活动 | 下限 5 分钟、均值 30 分钟、上限 60 分钟，日预算 15 次 |
| QQ 官方 | QQ 官方机器人平台的专用适配：合成消息投递、纯文本、分条与窗口控制 | 自动识别平台后启用；群聊主动消息默认关闭 |
| 高级 | 通用工具提示词和能力文案 | 通常保持默认 |
| 自主运行与状态 | 未读概况、联动状态、运行回执、心情与风格审批 | 信箱和状态默认开启；初始状态与风格为空 |
| 共享记忆与信箱 | 跨会话主脑共享记忆、未读信箱分流、点名通知卡、话题概括、群聊识图 | 全部默认关闭 |

## 消息与回复

输入防抖与回复节奏可以同时使用：前者减少重复模型请求，后者控制发送速度。AstrBot 已匹配的指令不合并、不延迟，也不计入刷屏轮数。图片和其它消息组件按原顺序保留，图片可提前转存以避免链接过期。

回复打断的边界：

1. 消息仍在合并窗口内：新消息并入同一批。
2. 模型正在生成，或第一条气泡尚未发出：允许打断后重新回答。
3. 第一条气泡已经发出：本轮继续说完，新回复排队。

拟人回复的群名单同时约束模型打断和发送接管。流式输出、WebChat、含媒体的回复和超过接管长度的回复交回原流程。

**OutputPro 先处理，拟人回复后发送**：文本清洗、艾特解析和普通消息的智能引用正常执行。OutputPro 已经分段、转发或发送时，本插件不会再次拆分尾段。合成事件使用的内部 UUID 不是 QQ 消息 ID，因此不添加指向该 UUID 的自动引用，已有真实引用仍保留。

## QQ 官方机器人（qq_official）适配

插件自动识别 `qq_official` / `qq_official_webhook` 平台并启用本组适配，其它平台行为不变；配置页「QQ 官方」分组可以逐项关闭。

1. **合成消息投递**：修复防抖合并后合成事件回复发不出去的问题。合成事件现在携带原始 botpy 消息对象与入站消息 ID，回复走被动回复（复用该 ID）而不是被适配器静默丢弃。
2. **纯文本与分条**：`qq_official_content_mode` 默认开启，回复统一发普通文本、不用 markdown（群里没有 markdown 权限时，声明 markdown 会先被平台拒绝、再由适配器去掉消息 ID 重试，既浪费主动消息配额又可能整条失败）；`qq_official_max_bubbles` 限制拟人回复的分条数量，超出部分按原顺序合并进最后一条，`0` 表示不限。
3. **回复窗口预算**：QQ 官方被动回复有效期 5 分钟。`qq_official_passive_window_seconds` 默认 240 秒，打字等待累计超过预算后，剩下的内容一次性立即发完，避免「前几条发出去了、后面的全部超窗失败」。
4. **主动消息**：私聊可用；群聊需要开启 `qq_official_group_proactive`，并且平台侧要有「主动消息」权限与配额。适配器的群场景缓存在进程内存里，重启后要等该群先来一条消息，群主动消息才能发出，未满足条件时预检会跳过并说明原因。
5. **平台固有限制**：群里只能收到 @ 机器人的消息，所以关键词唤醒、未读信箱、话题概括、群速览只能覆盖 @ 场景；没有戳一戳、正在输入状态、群成员信息和历史消息 API；出站 @ 目标必须是 openid，纯数字 QQ 号会被丢弃，占位 At 与 @全体 也会被清理；`qq_official_strip_at_markup` 负责把正文里残留的 `<qqbot-at-user id=…/>` 标记清掉。
6. **管理员与名单**：QQ 官方平台的管理员、白名单和主动消息目标要填 openid，而不是 QQ 号——`admins_id`、`proactive_target_whitelist` 填用户 openid，`proactive_allow_groups` 填群 openid。

## 范围与权限

- 各功能的群名单独立：排除名单优先；仅允许名单非空时只在其中生效；两者留空表示不限制。可以填群号或群名，私聊不受群名单影响。
- `user_whitelist` 是**免于刷屏拦截的用户**；`user_blacklist` 是**仅检测这些用户**，留空检测所有非免检用户。
- `blocked_users` 完全屏蔽本插件收到的聊天消息，包含指令。它不负责撤销其它插件在更早阶段已经采集的数据。
- `include_group`、`include_private` 只控制刷屏拦截，不控制防抖、聊天记录或长期记忆。
- 机器人回复只在成功发送后记入速览；未发送的生成内容不记录，部分失败只记录成功部分。普通回复和主动消息遵守同一记录名单。

## 聊天参考与记忆

模型可调用两个只读工具：`list_conversations` 列出其它会话，`read_conversation_messages` 按会话、发言人、时间和关键词查看消息。未传筛选条件时返回最近记录。

专属配置中心提供三种聊天参考方式，继续使用现有配置键：

| 方式 | `activity_prefetch_enabled` | `capability_context_digest` |
|---|---|---|
| 仅工具按需 | false | false |
| 关键词预取 | true | false |
| 每轮背景 | false | true |

旧配置同时开启后两项时，每轮背景优先，不重复附带记录。自动参考也遵守跨会话查看权限与私聊摘要开关。能力提醒只介绍本轮实际挂载的工具；待发清单仍仅向授权用户提供。自定义能力文案保留原文，请与启用的能力保持一致。

长期记忆网关需 LivingMemory，只在命中回忆触发词时检索。工具存在时只调用一次，返回空、失败或超时都不会重复查底层引擎；只有工具不存在时才尝试引擎，整次检索共用一个超时。

会话速览与长期记忆用途不同，保留两者。LivingMemory 全量采集发生在防抖拦截之前，可能同时采集原始碎片和合成全文；它当前没有公开的合成消息排除接口，需要跨插件适配，本插件不修改其私有缓存。

## 主动消息与自醒

主动消息通过 `send_message` 发出，正文由目标会话的人设和历史生成。生成失败不发送，不使用模板兜底。

- `proactive_allow_groups` 留空表示不允许向任何群主动发送。
- 私聊目标白名单是额外允许的用户；主人和管理员始终允许。
- 每目标默认每天最多 10 次、间隔至少 10 分钟、最多 3 条静默顺延中的待发消息。
- 默认静默时段为 00:00–08:00；开始与结束相同表示关闭。时段按机器人进程时区运行，页面显示实际时区。
- 不存在“问了没人回就自动追击”功能，也没有主动消息最短等待参数。

自主自醒和旧版判断式回退统一使用 `proactive_judge_provider_id`；留空使用全局默认模型，指定模型不可用时不自动换模型。记录保留实际模型 ID。自醒日预算限制判断次数，主动消息的日上限限制发送次数。

自醒基础工具为聊天记录、LivingMemory 记忆读取、AstrHe 读计划和更新待办、当前状态与风格提案、受控发信。其它工具通过 `resident_extra_tools` 逐项保存具体工具名，新安装的工具不会自动加入。基础工具仍受宿主、人设、会话、依赖插件及功能开关限制；最终请求与实际执行再次取交集。没有公开权限传递接口的嵌套分发、子代理和后台工具在自醒中不可用，页面会说明原因。普通聊天继续由宿主管理。

自醒沿用 AstrBot 主 Agent 和会话配置，在 Runner 初始化之前执行宿主的请求钩子，保留 AstrHe 的待办注入、计划读取与保密过滤，以及 LivingMemory、AstrNa 的原有请求处理。没有事情可以安静结束，不会在糯小喵另建每日规划、日记或长期记忆库。暂停等待执行边界，停止阻断之后的请求、工具和发送。

## 会话信箱

`list_conversations` 增加完整 `umo`、`unread` 和 `unread_mentions`。普通查询仍默认不列当前会话，自醒会列入当前锚定会话。`read_conversation_messages` 不传新参数时保持原查询行为；显式传入 `mode=recent/unread/mentions` 使用稳定记录 ID 分页，返回 `next_before_id`、`has_more` 和截断标记。

`mark_read=true` 只标记本次实际返回的消息；默认不标记。提及模式包含前文，不会清空群里其它未读。通过 `before_id` 翻页默认不改阅读状态。普通对话成功完成模型请求后，合并消息按原始消息 ID 逐条去重并确认已读；失败请求保留未读。已读按人设区分，查询和回执以平台、消息类型和会话 ID 隔离。聊天记录群名单也支持完整 `平台ID:GroupMessage:群号`；旧群号/群名写法保持原范围。

信箱沿用记录范围、保留天数和正文长度；关闭记录的会话不会重新开放读取。首次升级时现有记录作为历史，不产生历史未读积压。已有纯媒体消息的记录方式保持不变。

## 共享记忆与信箱

2.3.0 起提供一组可选的跨会话能力（**全部默认关闭**，不影响已有行为）。开启后使用「共享记忆与信箱」分组的配置；关闭时相关工具与钩子不参与请求。

### 全局主脑共享记忆

开启后，模型每轮请求都读写同一个「主脑」会话的连续历史：跨群、跨私聊不断片。实现上不复制消息：等待 LLM 时按需把主脑会话绑定到本轮请求，并发的聊天回合串行持锁（同任务可重入），避免历史互相覆盖；请求结束自动放锁。人设、心情、关注点和风格仍按真实会话解析，不会串到别处。

- `master_umo` 显式指定主脑会话（完整 `平台ID:GroupMessage:群号` 或 `平台ID:FriendMessage:QQ`）。
- 留空且开启 `master_auto_bind`（默认开启）时，首次收到管理员私聊消息自动把该会话绑定为主脑并持久化。
- 静默自醒轮次不抢主脑锁、不重绑主脑，只在自己的会话里思考，写完小结才排队写回。

### 未读信箱分流

开启后，群里**未 @、未命中关键词、非指令**的普通消息不再回复：立即停止事件、收进未读信箱，并在后台触发话题概括；点名、关键词唤醒、私聊与指令永远即时回复。分流的群消息仍会记入聊天速览，`read_conversation_messages` 的未读/提及模式与点名通知卡都能看到它们。

- `inbox_group_whitelist` / `inbox_group_blacklist`：只在名单内的群分流（留空不限），排除名单优先。

### 点名通知卡

开启后，@ 或关键词唤醒时在提示中注入本会话的未读情况、近期话题与最近未读消息，并把当前会话整体标记已读，防止「被点名的群」继续计入未读。`mention_notice_limit` 控制最多带多少条最近未读。

### 话题概括

开启后，后台轻量模型把一段未读聊天压成一句话题，注入会话清单（`list_conversations` 的 `topic` 字段）与点名通知卡；单会话视角读取时也会附带 `topic`。概括是分段的：每攒够一段（`topic_segment_msg_count`）落一条记录，游标推进；冷却期内不重复概括，避免高频群反复烧模型。

- `topic_light_provider_id`：指定话题模型；留空使用会话默认模型，指定模型不可用时本轮跳过、不自动换模型。
- `topic_min_unread` / `topic_cooldown_seconds` / `topic_max_chars` / `topic_line_max_chars` / `topic_timeout_seconds` / `topic_segment_msg_count` / `topic_segment_backfill_max` 控制触发与长度。
- 概括失败（超时、无模型、输出无法解析）只跳过本轮，不落段、不推游标。

### 群聊识图

开启后，群里发来的图片被留底到插件数据目录（含纯图片消息，未开启时纯图片消息仍不进速览库），并在后台自动转述。模型可用新工具 `read_image` 按「会话 + 消息编号 + 图片序号」查看任意一张留底图并回答关于它的问题：

1. 先用 `list_conversations` 拿到会话的 `umo`；
2. 再用 `read_conversation_messages` 找到带图消息的 `id`；
3. 调用 `read_image(conversation, message_id, index, question)`。

留底按 `image_keep_days` 清理（默认 3 天），描述缓存按 `vision_cache_ttl_days` 清理；`vision_image_max` 限制单条消息最多留底张数，`vision_brief_max_chars` 控制自动转述长度，`vision_read_max_chars` 控制工具回答长度，`vision_timeout_seconds` 控制单次识图超时。模型链为 `vision_provider_ids`（按顺序回退）→ AstrBot 默认识图模型 → 会话默认模型；读取遵守跨会话查看权限（默认仅管理员可用）。

### 许可与移植边界

本组能力的行为设计参考了 [astrmia](https://github.com/Kalospacer/astrbot_plugin_astrmia) 插件，但按「独立重实现」原则编写：astrmia 仓库没有 LICENSE 文件、默认保留所有权利，因此本插件**没有复制其任何源码**，仅按其公开文档与行为描述重新实现。来源与边界详见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 状态、风格与运行记录

`nuoxiaomiao_update_state` 只共享枚举心情及 0–100 强度；原因、人物信息和关注点保存到来源会话。不同人设完全隔离。状态通过临时内容提供，不改聊天历史。`nuoxiaomiao_propose_style` 仅创建待审提案；管理员在“自主运行与状态”查看差异并批准后，建议才作为独立风格补充生效，不覆盖基础人设。批准要求风格版本及基础人设文本版本一致；支持拒绝和回滚。

自醒在第一次模型请求前持久扣次，失败也计入，重启不重置当天累计。工具请求、工具执行回执和实际发送分别保存。被拒绝或顺延的发送不算已发言，平台异常无法确认结果时进入待核实列表，不能自动重放。

`resident_run_token_limit` 与 `resident_daily_token_limit` 默认 `0`，表示不额外限制。阈值统计未缓存输入加输出，缓存输入单独展示；按请求当天累计。一次请求可能越过阈值，之后停止继续请求。启用阈值且缺少用量时停止后续请求。统计覆盖本插件经过宿主模型入口的自主请求及压缩、目标消息生成；第三方工具内部没有报告给宿主的模型调用不能推算用量。

重启后未开始模型请求的记录在下一次有效自醒恢复；已经执行但失去回执的动作标记未知，需在页面核实，核实操作不会重放。静默顺延保留原运行预算，页面显示待发记录，停止本轮会取消尚未执行的顺延消息；原有过期发送宽限规则继续生效。以上账本只管理糯小喵的自主活动，AstrHe 的独立任务仍由其自身管理。

记忆、关系和规划管理链接打开各自插件的已有页面；缺少依赖或公开接口时显示不可用，不自动启用依赖，也不读取其私有数据库。

## 默认设置与升级

- **保存并设为我的默认**：保存本次提交并建立个人默认快照。
- **应用我的默认 / 应用出厂默认**：填入草稿，保存后生效。
- **删除我的默认快照**：只删除快照，不改变当前配置和草稿。

插件目录名保持 `astrbot_plugin_nuoxiaomiao`；注册名保持 `astrbot_plugin_nuoxiaomiao`，必须与会话的 `plugin_set` 一致。配置文件是 AstrBot 的 `data/config/astrbot_plugin_nuoxiaomiao_config.json`；聊天速览、本地化图片与「我的默认」快照默认位于 AstrBot 的 `data/plugin_data/astrbot_plugin_nuoxiaomiao/`（更新/重装插件不覆盖）。

加载时会在 AstrBot 补默认值之前处理旧配置文件名和两个别名：`merge_enabled` → `debounce_enabled`、`poke_reply_debounce_seconds` → `poke_reply_cooldown_seconds`。已有新键优先。别名迁移保留 `.bak-alias-<摘要>` 原始文件备份，原子写入，可重复执行；个人默认快照也兼容迁移。

2.2.0 首次加载会在记录库旁保存 `config.before-resident-v1.json` 配置备份；已有 SQLite 记录库保存 `.bak-resident-v1` 备份，再以事务执行可重复的增量迁移。旧非空插件选择冻结为迁移当时可用的具体工具；旧“空名单＝全部”改为基础工具，页面显示迁移说明。状态、风格版本和运行账本不随聊天记录过期清理。恢复备份前请先停用插件，SQLite 应使用备份文件整体恢复，不在运行中覆盖数据库。

2.3.0 首次加载会在同一记录库上做可重复的增量迁移：新增话题分段表、识图留底表与描述缓存表，其余数据原样保留，不产生未读积压；新功能全部默认关闭，升级前行为不变。迁移前先备份记录库（同 2.2.0 的恢复方式）。

也可手动执行 `python scripts/migrate_config.py`。当前配置存在时不会被旧文件覆盖。推荐将 `force_wake_prefix` 留空，自动读取实际会话唤醒前缀。
